## Findings

### V1. The lab still logs 19 reloads, and they are the shell's, one per deleted path

- What: `omakit lab conform ~/Projects/omarchy/omaboot#plugin`, count of
  `Local plugin changed, reloading: mtolhuys.omaboot` in
  `omakit-lab/shell-log-filtered.txt`.
- Saw: 19, exactly as in the test round: one at `16:18:50` (the install)
  and 18 in the same second, `16:19:26`, as the last 18 lines of the guest
  shell's log (`omakit-lab/shell-log.txt` lines 39 to 56), under the shell
  restarted by `lab-restart`.
- Expected: one per real change, per section 4 item 1, which the fix round
  tied to the harness work directory inside `plugin/`.
- Cause: not the harness. The guest installs the subject with
  `omarchy-plugin-add`, a `git clone` at the subject commit staged as a
  hidden directory and moved into place in one `mv` (one event, the one
  line at install; the harness work directory was never in the guest, it
  was git-ignored). The pinned shell's `PluginRegistry.qml` (lines 663 to
  679) runs `inotifywait -m -r -e close_write,create,delete,move` on the
  plugins directory and emits `localPluginChanged` for every event, with no
  coalescing; `localPluginIdForPath` (line 728) ignores hidden entries and
  `.git`. `lab-remove` runs `omarchy-plugin-remove`, whose `rm -rf` (line
  103) deletes 16 tracked files, `plugin/harness` and the plugin directory:
  18 events, 18 lines. The expectation cannot be met by anything in this
  repository; the number is the size of the plugin tree.
- Reproduce: `jq -r '[.id,.result]|@tsv' omakit-lab/checks.jsonl` and
  `grep -n 'reloading: mtolhuys.omaboot' omakit-lab/shell-log.txt`; the
  line count is `git ls-tree -r HEAD --name-only plugin | wc -l` plus two,
  plus one. On a host shell: copy a plugin tree into
  `~/.config/omarchy/plugins/` and `rm -rf` it while watching
  `journalctl --user -f` (not done in this round; it touches the running
  shell's plugin directory).

### V2. `shots.sh` exits 0 when `render.py` cannot start

- What: `plugin/harness/shots.sh /tmp/omaboot-shots` on a machine whose
  `python3` has no PySide6 (the state of this machine at the start of the
  round).
- Saw: nine lines `ModuleNotFoundError: No module named 'PySide6'`, no
  picture written, `exit: 0` in 0 s. The pictures from the previous day were
  still in the directory, so a reader of the directory alone would take the
  run as passed.
- Expected: a non-zero exit and one sentence naming PySide6, as `render.py`'s
  own header (`Needs: PySide6 (pip install PySide6)`) suggests.
- Cause: `plugin/harness/shots.sh:8`: `render()` pipes `render.py` through
  `grep -i "wrote\|error\|warning" || true`, so the interpreter's exit
  status never reaches `set -e`; `exercise.sh:18` has the same shape but
  its `expect` checks fail on the missing log lines, and `theme-follow.sh`
  fails on the missing colours, so only `shots.sh` is silent.
- Reproduce: `PATH=/usr/bin plugin/harness/shots.sh /tmp/x; echo $?` on a
  machine where `/usr/bin/python3` has no PySide6.
