# Fix round, 20 September 2026

The findings of the test round of 19 September 2026
(`test-round-2026-09-19.md`), worked through in order, one commit per finding
or per tightly related pair. Nothing was applied, reverted or reset on any
machine; every system-touching path stayed under `--dry-run` or a prefix.
Evidence for every row is in `docs/evidence/fix-round-2026-09-20/`.

## 1. Where this ran

The engine, the harness and the checks ran in a Linux container with no
Omarchy shell, no Quickshell and no QEMU: rustc/cargo 1.95.0, PySide6 6.11.2,
JetBrainsMono Nerd Font as fontconfig's `monospace`, and a fresh clone of
upstream `omacom/omarchy` at `e38c1d1` on the `quattro` branch (version
`4.0.0.alpha`, 19 September 2026) as `OMARCHY_PATH`. The harness scripts ran
with `XDG_CONFIG_HOME` and `XDG_STATE_HOME` set, the way a login shell has
them, which is the environment finding F2 failed in. Everything that needs
the reference machine or the lab is under "Needs a human".

## 4. Needs a human

Everything here needs the reference machine, the running shell or the lab.

1. **The lab, including the log gate (F7) and the reload count (F8).** With
   the tree clean:

   ```bash
   OMAKIT_PLUGIN_LAB=~/Projects/omarchy/plugin-lab ~/Projects/omarchy/omakit/bin/omakit lab conform ~/Projects/omarchy/omaboot#plugin
   ```

   Expected: `lab-log-gate` passes (no `Process failed to start` line, since
   the window now finds no engine and spawns nothing), and
   `shell-log-filtered.txt` shows one `Local plugin changed, reloading:
   mtolhuys.omaboot` per real change instead of about twenty. Put the log
   in `docs/evidence/fix-round-2026-09-20/omakit-lab/`. If the guest still
   reloads repeatedly, the cause is in the guest, not the harness work
   directory, which no longer exists inside `plugin/`.

2. **`omaboot` right after `omaboot plugin install` (F6).**

   ```bash
   omaboot plugin uninstall; omaboot plugin install && omaboot
   ```

   Expected: the window, within a few seconds; or, if the shell takes
   longer than ten seconds, a sentence saying it was still reloading and to
   run `omaboot` again. Also check that the installed shell answers
   `omarchy-shell shell call mtolhuys.omaboot ping ""` with `open` while
   the window is up: the polling was written against upstream `e38c1d1`,
   and `docs/UPSTREAM.md` says the installed tree has not been read for
   `call`. Without it `omaboot` behaves as before (one summon, trusted).

3. **`omaboot status --json | jq .active_omarchy_theme` (F5)** on the
   machine where `current/theme` is a directory: expected the name from
   `theme.name` (Catppuccin Dark during the test round), and the "Your
   Omarchy theme" row back in the colour popup.

4. **`qmllint plugin/*.qml`**: not available in the container. Every file
   loaded and rendered in the harness, which catches more than syntax, but
   the lint is part of the definition of done.

5. **The harness on the reference machine, in a normal login shell**, without
